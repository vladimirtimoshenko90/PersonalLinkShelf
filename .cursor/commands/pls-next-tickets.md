# PLS Next Tickets

Analyze only. Do not write code, edit files, change git, or change Jira statuses.

1. Read this repo: layout, `package.json`, `manifest.config.ts`, and `src/` (what exists vs empty placeholders).
2. Read recent git history (`git log`) and uncommitted changes (`git status`, `git diff`) so proposals do not redo work already landed or in progress locally.
3. Open the Jira project **PLS** (Personal Link Shelf) via the Atlassian MCP. Read To Do / In Progress / Done. Prefer board order (`key ASC` among To Do tasks). Read each candidate ticket’s description, not only the summary.
4. If Confluence space **PLS** is needed to judge a ticket (Domain entities, Storage schema, UI/UX), read those pages.

Propose **2 or 3** next tickets we may take. For each: key, summary, why it is next (dependencies and what the codebase already has), and what “done” means from the ticket. If two tickets must stay in a fixed sequence, say so.

Do not move tickets. Do not implement. Do not invent extra work that is not on the board.
